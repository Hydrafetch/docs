---
title: "Caching"
description: "Reuse a recent copy of a page to get answers faster, or always fetch fresh when you need the latest."
---

We keep a recent copy of the pages we read. When you scrape a URL we read recently, we can answer from that copy instead of fetching the page again. The answer comes back faster, and it costs the same as a fresh read.

By default a scrape accepts a copy up to **2 days** old for a page and **1 hour** old for a feed. Three options change that.

## `maxAge`

The oldest copy you will accept, in **milliseconds**. If our newest copy is older, or we have none, the page is fetched fresh.

```bash
curl -X POST https://api.hydrafetch.com/v1/web/scrape \
  -H "X-API-Key: hf_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com",
    "maxAge": 3600000
  }'
```

<ParamField body="maxAge" type="number">
  `3600000` accepts any copy from the last hour. `0` always fetches fresh. Leave it out for the default. The most you can set is 7 days, `604800000`.
</ParamField>

Pick it by how often the page changes. A price or a status page wants a short window or `0`. A documentation page can take the default.

## `cacheOnly`

Answer only from a copy, and never fetch. If there is no copy young enough, you get `404` instead.

```bash
curl -X POST https://api.hydrafetch.com/v1/web/scrape \
  -H "X-API-Key: hf_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com",
    "cacheOnly": true
  }'
```

Use it for backfills and replays, where you want what we already have and nothing new.

<Warning>
  With `cacheOnly`, a missing copy is a `404` and no page is fetched. Handle that status in your code.
</Warning>

## `storeInCache`

Whether this read is kept as a copy for later calls. On by default. Turn it off for one-off or sensitive pages you do not want kept.

<ParamField body="storeInCache" type="boolean" default="true">
  Keep this read so later calls within their `maxAge` can be answered from it.
</ParamField>

## Telling a copy from a fresh read

A response from a copy says so in two places:

```json
{
  "data": {
    "url": "https://example.com",
    "cached": true,
    "usage": { "creditsUsed": 1, "creditsRemaining": 499, "freshness": "cache" }
  }
}
```

- `data.cached` is `true`.
- `data.usage.freshness` is `cache`. A live read says `fresh`.

Blocked and very thin results are never kept, so a retry always fetches the page again rather than repeating a bad copy.

## Other endpoints

- `extract`, `images`, `screenshot` and `styleguide` take `maxAge` the same way, with `0` for fresh.
- In a crawl, a batch or a search with `scrapeResults`, put `maxAge` inside `scrapeOptions` to apply it to every page.
- [News](/endpoints/news) never answers from a copy: every call reads the news fresh.
