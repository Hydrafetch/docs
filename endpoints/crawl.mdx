---
title: "Crawl"
description: "Find and read every page of a site as one background job."
---

`POST /v1/web/crawl` starts from a URL, finds the site's pages and reads each one. It runs as a background job: you get a `crawlId` straight away, then poll it or let a webhook tell you as pages finish. 1 credit per page read.

## When to use it

- You want every page of a site, or of one section, and you do not have the list of URLs.
- The job is too big to wait for in one request.

If you already have the URLs, use [Batch](/endpoints/batch). To see which URLs a crawl would reach without reading them, use [Map](/endpoints/map).

## Example

<CodeGroup>

```bash cURL
curl -X POST https://api.hydrafetch.com/v1/web/crawl \
  -H "X-API-Key: hf_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/blog",
    "limit": 100,
    "maxDepth": 2,
    "includePaths": ["^/blog"],
    "excludePaths": ["^/blog/tag"],
    "scrapeOptions": { "formats": ["markdown", "links"] }
  }'
```

```javascript Node
import { Hydrafetch } from "@hydrafetch/node-sdk";

const hf = new Hydrafetch(process.env.HYDRAFETCH_API_KEY);
const job = await hf.crawlAndWait("https://example.com/blog", {
  limit: 100,
  maxDepth: 2,
  includePaths: ["^/blog"],
  excludePaths: ["^/blog/tag"],
  scrapeOptions: { formats: ["markdown", "links"] },
});
job.pages.forEach((p) => console.log(p.url, p.status));
```

```python Python
import requests

res = requests.post(
    "https://api.hydrafetch.com/v1/web/crawl",
    headers={"X-API-Key": "hf_your_key_here"},
    json={
        "url": "https://example.com/blog",
        "limit": 100,
        "maxDepth": 2,
        "includePaths": ["^/blog"],
        "excludePaths": ["^/blog/tag"],
        "scrapeOptions": {"formats": ["markdown", "links"]},
    },
)
crawl_id = res.json()["crawlId"]
```

</CodeGroup>

The crawl starts at once:

```json
{ "crawlId": "019f3c09-6fae-740f-9257-10c2b6af7f43", "status": "queued" }
```

## Keeping a crawl inside one section

A starting URL says where to begin, not where to stay. To find pages, a crawl also reads the site's published page list (its sitemap), which covers the whole site. So a crawl started at `https://example.com/blog` with nothing else set will also return pages from the rest of the site.

To stay inside the section, add `includePaths`, written so the starting page matches it too:

```json
{ "url": "https://example.com/blog", "includePaths": ["^/blog"] }
```

`["^/blog/"]`, with the trailing slash, works the same way. If your patterns would exclude the starting page, the crawl has nowhere to begin, so the request is refused instead of starting a job that finds nothing.

## Options

<ParamField body="url" type="string" required>
  Where to start. Must be http or https.
</ParamField>

<ParamField body="limit" type="number" default="100">
  The most pages to read, from 1 to 500.
</ParamField>

<ParamField body="maxDepth" type="number" default="3">
  How many links away from the starting page to follow, from 0 to 10.
</ParamField>

<ParamField body="includePaths" type="string[]">
  Only follow URLs whose path matches every one of these patterns, such as `["^/blog"]`. Up to 50. **They apply to the starting URL too.**
</ParamField>

<ParamField body="excludePaths" type="string[]">
  Skip URLs whose path matches any of these patterns, such as `["^/blog/tag"]`. Up to 50. They also apply to the starting URL.
</ParamField>

<ParamField body="allowSubdomains" type="boolean" default="false">
  Also follow links into the site's subdomains.
</ParamField>

<ParamField body="allowExternalLinks" type="boolean" default="false">
  Also follow links that leave the site.
</ParamField>

<ParamField body="ignoreQueryParameters" type="boolean" default="false">
  Treat URLs that differ only in their query string as the same page.
</ParamField>

<ParamField body="sitemap" type="string" default="include">
  Whether to use the site's published page list to find pages: `include` or `skip`. Because that list covers the whole site, starting from a section does not keep the crawl in that section. Use `includePaths` for that.
</ParamField>

<ParamField body="scrapeOptions" type="object">
  How to read each page. The same options as a [Scrape](/endpoints/scrape), with formats limited to `markdown`, `html`, `rawHtml`, `links` and `structured`.
</ParamField>

<ParamField body="webhook" type="object">
  Have us call your URL as pages finish and when the job ends, instead of polling. See [Jobs & webhooks](/concepts/jobs-and-webhooks#crawl-and-batch).
</ParamField>

## Getting the results

Poll `GET /v1/web/crawl/{id}` for progress and each finished page. Results stay available for 90 days after the crawl last changes. After that the call answers `404`.

```bash
curl https://api.hydrafetch.com/v1/web/crawl/019f3c09-6fae-740f-9257-10c2b6af7f43 \
  -H "X-API-Key: hf_your_key_here"
```

```json
{
  "data": {
    "id": "019f3c09-6fae-740f-9257-10c2b6af7f43",
    "kind": "crawl",
    "status": "running",
    "seedUrl": "https://example.com/blog",
    "total": 100,
    "completed": 42,
    "failed": 1,
    "creditsUsed": 42,
    "pages": [
      {
        "url": "https://example.com/blog/post",
        "status": "completed",
        "depth": 1,
        "discoveredVia": "sitemap",
        "error": null,
        "data": {
          "url": "https://example.com/blog/post",
          "finalUrl": "https://example.com/blog/post",
          "status": 200,
          "cached": false,
          "metadata": { "title": "A post", "pageType": "article", "wordCount": 812 },
          "markdown": "# A post\n\n..."
        }
      }
    ]
  }
}
```

<ResponseField name="data.status" type="string">The job's state: `running`, `completed`, `failed` or `cancelled`.</ResponseField>
<ResponseField name="data.total" type="number">How many pages the job holds.</ResponseField>
<ResponseField name="data.completed" type="number">Pages read so far.</ResponseField>
<ResponseField name="data.failed" type="number">Pages that could not be read.</ResponseField>
<ResponseField name="data.creditsUsed" type="number">Credits used so far, 1 per page read.</ResponseField>
<ResponseField name="data.pages" type="object[]">
  Each page with its `url`, `status` (`queued`, `running`, `completed` or `failed`), `depth`, `discoveredVia` and `data` once it is read. A failed page also has `error`, an `errorCode` and `retryable`, which says whether asking again could help. `requestedUrl` is the URL as you gave it, and appears only when it differs from `url` after we normalised it.

  `discoveredVia` says how the URL got into the job: `requested` for the starting URL, `sitemap` for one from the site's page list, and `link` for one followed from a page we read. It is the quickest way to see why a crawl returned what it did, and whether a higher `limit` or `maxDepth` would find more.
</ResponseField>

## Cost

1 credit per page read. Pages that fail are free. Set `limit`, `maxDepth` and path filters to keep the cost predictable, and check the reach first with [Map](/endpoints/map).
