---
title: "Scrape"
description: "One URL in, clean data out, in the formats you ask for."
---

`POST /v1/web/scrape` reads one URL and returns it the way a model wants to read it: clean Markdown, the page's own structured data, its links, a summary or JSON in your schema. You choose the formats and how the page is fetched. We handle the rest, including pages that need JavaScript to show their content.

## When to use it

- You have a URL and want its content now.
- You want more than text: the page's structured data, its links or a summary.
- You need control over the fetch: wait for slow content, read as if from another country, or send your own headers.

For a whole site, use [Crawl](/endpoints/crawl). For a list of URLs, use [Batch](/endpoints/batch).

## Example

<CodeGroup>

```bash cURL
curl -X POST https://api.hydrafetch.com/v1/web/scrape \
  -H "X-API-Key: hf_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com",
    "formats": ["markdown", "links", "structured"]
  }'
```

```javascript Node
import { Hydrafetch } from "@hydrafetch/node-sdk";

const hf = new Hydrafetch(process.env.HYDRAFETCH_API_KEY);
const page = await hf.scrape("https://example.com", {
  formats: ["markdown", "links", "structured"],
});
console.log(page.markdown);
```

```python Python
from hydrafetch import Hydrafetch

hf = Hydrafetch()
page = hf.scrape("https://example.com", formats=["markdown", "links", "structured"])
print(page["markdown"])
```

</CodeGroup>

## Options

### What to return

<ParamField body="url" type="string" required>
  The URL to read. Must be http or https. A bare domain such as `example.com` is read over https.
</ParamField>

<ParamField body="formats" type="string[]" default="[&quot;markdown&quot;]">
  Any of `markdown`, `html`, `rawHtml`, `links`, `structured`, `summary`, `json` and `brand`. See [Formats](/concepts/formats) for what each returns and costs.
</ParamField>

<ParamField body="jsonOptions" type="object">
  For the `json` format: a `schema` (JSON Schema for the shape you want), a `prompt` (what to look for), or both. One is required when you ask for `json`.
</ParamField>

<ParamField body="preferStructure" type="boolean" default="false">
  Keep headings, lists and tables, even at the cost of some prose. Good for marketing and service pages, where the headings are the content. Left off, we aim to capture every word, which suits articles but can flatten listing pages into plain text. If `metadata.structure` comes back `plain` and you wanted structure, retry with this on.
</ParamField>

<ParamField body="includeLinks" type="boolean">
  Keep links inline in the Markdown. By default links are kept where the page's text relies on them. `true` keeps them everywhere; `false` gives the densest prose.
</ParamField>

### Filtering the page

<ParamField body="onlyMainContent" type="boolean" default="true">
  Return only the main content, without menus, headers and footers.
</ParamField>

<ParamField body="includeTags" type="string[]">
  CSS selectors to keep. When set, only matching elements are used. Up to 50.
</ParamField>

<ParamField body="excludeTags" type="string[]">
  CSS selectors to remove before reading. Up to 50.
</ParamField>

<ParamField body="removeBase64Images" type="boolean" default="true">
  Remove images embedded as base64 text.
</ParamField>

<ParamField body="blockAds" type="boolean" default="true">
  Remove common ad and tracking elements.
</ParamField>

### How the page is fetched

<ParamField body="waitFor" type="number">
  Extra milliseconds to let the page settle before reading it, from 0 to 30000.
</ParamField>

<ParamField body="timeout" type="number">
  The time budget for the call in milliseconds, from 1000 to 100000.
</ParamField>

<ParamField body="location" type="object">
  Read the page as if from another place. `country` is a two-letter code such as `"us"`. `languages` lists preferred languages, most preferred first, such as `["en-US", "en"]`.
</ParamField>

<ParamField body="headers" type="object">
  Extra headers to send to the site, such as a cookie that picks a store or a region.
</ParamField>

<ParamField body="method" type="string" default="GET">
  `GET` or `POST`. Use `POST` for addresses that only answer a POST, such as JSON and GraphQL APIs.
</ParamField>

<ParamField body="body" type="string">
  The request body to send with `POST`, as written. Set its content type yourself in `headers`.
</ParamField>

### Caching

<ParamField body="maxAge" type="number">
  The oldest copy you will accept, in milliseconds. By default 2 days for a page and 1 hour for a feed. `0` always fetches fresh. At most 7 days. See [Caching](/concepts/caching).
</ParamField>

<ParamField body="cacheOnly" type="boolean" default="false">
  Answer only from a copy. With no copy young enough, return `404` instead of fetching.
</ParamField>

<ParamField body="storeInCache" type="boolean" default="true">
  Keep this read as a copy for later calls.
</ParamField>

### Waiting

<ParamField body="async" type="boolean" default="false">
  Answer at once with a job id instead of waiting for the page. Poll `GET /v1/web/scrape/{id}`.
</ParamField>

<ResponseField name="data" type="object">
  <Expandable title="WebScrapeData">
    <ResponseField name="url" type="string">The URL you asked for.</ResponseField>
    <ResponseField name="finalUrl" type="string">Where the page ended up after redirects.</ResponseField>
    <ResponseField name="redirected" type="boolean">Whether the page redirected.</ResponseField>

## Shortcuts for one format

These take the same options as `/v1/web/scrape` and return the same response, with the format already chosen:

| Endpoint | Returns |
| --- | --- |
| `POST /v1/web/markdown` | Markdown |
| `POST /v1/web/html` | Cleaned HTML |
| `POST /v1/web/raw-html` | The original HTML |
| `POST /v1/web/links` | Links |
| `POST /v1/web/structured` | The page's structured data |

## Waiting for a result

A scrape waits for the page and returns it, for up to **90 seconds**. Past that it fails with `504` and `REQUEST_TIMEOUT`, and costs nothing. It never turns into a job by itself, so one URL always means one response shape: the page, or an error saying why not. The read usually carries on in the background, so a retry often comes back quickly from our cache.

<Note>
  Set your own client timeout below 90 seconds if you want to give up sooner. Anything longer will never be reached.
</Note>

To skip the wait, send `async: true`. You get a job id at once:

```json
{ "jobId": "019f3c09-6fae-740f-9257-10c2b6af7f43", "status": "queued" }
```

Then poll it:

<CodeGroup>

```bash cURL
curl https://api.hydrafetch.com/v1/web/scrape/019f3c09-6fae-740f-9257-10c2b6af7f43 \
  -H "X-API-Key: hf_your_key_here"
```

```python Python
import requests

res = requests.get(
    f"https://api.hydrafetch.com/v1/web/scrape/{job_id}",
    headers={"X-API-Key": "hf_your_key_here"},
)
job = res.json()
```

</CodeGroup>

The job's `status` is `waiting`, `active`, `completed` or `failed`, with `data` once completed or `error` if it failed.

## Cost

1 credit per page read, plus 1 for `summary`, 4 for `json`, and 5 for `brand` when a brand is found. A page we cannot read costs nothing. See [Credits](/concepts/credits).
